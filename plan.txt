Etapa 2 — Contexto bajo demanda ✅ La más sólida y la base. Hoy el ContextEngine ya construye el índice estructural (archivos/símbolos/deps) y el Optimizer ya selecciona por keywords con TokenBudget — pero el contexto semántico se construye para todo el proyecto. Separar los dos niveles (índice barato siempre / semántica cara solo para el subgrafo relevante) encaja perfecto con el .context/graph.json que ya creamos. La invalidación por cambio de archivos es lo único realmente nuevo (hoy el cache en .satellite/context/context.json no tiene mtime). Riesgo bajo, alto valor.

Etapa 3 — LLM local (Gemma 4 E2B + llama.cpp) ⚠️ La más arriesgada técnicamente. Antes de empezar hay que verificar: (a) si en third_party/llama-b10739-bin-win-vulkan-x64 está solo el binario de llama.cpp o también el GGUF de Gemma (un GGUF de Gemma 4 E2B pesa 2-8GB — si no está, hay que descargarlo); (b) el build Vulkan requiere GPU Vulkan — en Linux/macOS o máquinas sin Vulkan no corre → hace falta fallback CPU (el patrón de invocar binarios externos ya existe en el framework: la AgentFactory invoca g++ como subproceso — llama-cli sería igual). La latencia local sin costo API es el gran atractivo; el benchmark se puede extender para medir el trade-off compresión-vs-calidad.

Etapas 4-5 ✅ Coherentes con lo existente: el Planner ya genera subtareas — hoy el contexto se comparte entre microagentes; cambiarlo a contexto por subtarea es un cambio acotado en el Orchestrator. El "actualizar contexto tras resultados" conecta con el ExecutionLogger (ya registra todo).

Etapa 6 — Contexto propiedad de Satellite ✅ Ya casi se cumple: el formato (ProjectContext JSON) es neutro, no depende del provider. El cambio de modelo sin reconstruir es más una garantía de diseño que trabajo nuevo.

Etapa 7 — MCP Server 🎯 La de mayor valor para el proyecto. MCP es JSON-RPC sobre stdio — implementable en C++17 con nlohmann sin dependencias nuevas. El esquema de tools de contexto (query_graph, get_context, invalidate) se define antes. Localmente se puede probar con Hermes y OpenCode; Claude Code/OpenClaw habría que instalarlos o probarlos en otra máquina.

Etapa 8 — Multi-provider ✅ Fácil: ILLMProvider ya es una abstracción con el adapter de DeepSeek. Ojo: Claude NO es OpenAI-compatible (API Anthropic propia) → necesita su propio adapter; el resto (GPT, Grok, local) son OpenAI-compatible y se cubren con un adapter genérico.
